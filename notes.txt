Nesta aula vamos criar constraints de validação customizadas usando composição.

Vide a anotação TaxaFrete

@Target(...) -> define o que pode ser anotado
@Retention(...) -> define em que momento a anotação se aplica. Compilação, runtime...
@Constraint(...) -> define uma ou mais classes que vão validar programaticamente
@PositiveOrZero -> define que essa anotação vai validar a anotação @TaxaFrete

public @interface TaxaFrete {

    @OverridesAttribute(constraint = PositiveOrZero.class, name = "message") -> define que a mensagem será sobreescrita
    String message() default "{TaxaFrete.invalida}";

    Class<?>[] groups() default {};

    Class<? extends Payload>[] payload() default {};
}


Um problema que acontece é que quando temos no arquivo messages.properties as seguintes propriedades:

    PositiveOrZero={0} deve ser maior ou igual a zero
    TaxaFrete.invalida={0} está inválida

Mesmo que usemos a anotação:

    @OverridesAttribute(constraint = PositiveOrZero.class, name = "message")

A mensagem lançada será: Taxa de Frete deve ser maior ou igual a zero
Isto acontece porque a violação da constraint é lançada como PositiveOrZero ao invés de TaxaFrete. Este acaba sendo um
problema ao criar anotações customizadas usando composição.
